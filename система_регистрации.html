🗄️ База данных (PostgreSQL / MongoDB)

// Коллекция/таблица: users
{
email: string, // уникальный, primary key
passwordHash: string, // bcrypt + соль

status: 'standard' | 'premium' | 'admin', // статус пользователя

// Токен (один на пользователя)
token: string | null, // случайная строка 64 символа
tokenExpiresAt: Date | null, // всегда +7 дней от последнего обновления

// Слепок устройства
fingerprint: string | null, // хеш устройства (SHA-256)

// Для подтверждения email (регистрация)
verificationCode: string | null, // 6 цифр
verificationCodeExpiresAt: Date | null, // +15 минут
// Для восстановления пароля
resetCode: string | null, // 6 цифр
resetCodeExpiresAt: Date | null // +15 минут
}

📊 Статусы пользователя

standard — обычный пользователь
premium — премиум-доступ
admin — администратор

📧 Коды подтверждения и восстановления

🔢 Формат кода

6 случайных цифр (например: 483921)

Срок жизни: 15 минут

Пользователь вводит email

6 цифр, срок 15 мин

🔐 Важно: После успешного подтверждения код сразу удаляется из БД (становится null). Повторно использовать тот же код нельзя.

Сценарий 1: Подтверждение регистрации

1. POST /register → генерируем verificationCode >-
2. Отправляем код на email
3. POST /verify → проверяем verificationCode
4. При успехе: verificationCode = null, status = 'standard'

Сценарий 2: Восстановление пароля

1. POST /forgot-password → генерируем resetCode
3. POST /reset-password → проверяем resetCode
4. При успехе: resetCode = null, обновляем пароль

🔄 Эндпоинты API

POST /api/auth/register

Цель: Создать пользователя, отправить код подтверждения

ПараметрТипОписание
emailstringEmail пользователя
passwordstringПароль (мин. 8 символов)

Успех (200):

{ "message": "Код подтверждения отправлен на email" }

Логика:

1. Проверить, нет ли пользователя с таким email
2. Создать запись:
- status = 'standard' // сразу standard!
- verificationCode = generate6DigitCode()
- verificationCodeExpiresAt = now + 15min
- passwordHash = bcrypt.hash(password)
- token = null (пока нет)
3. Отправить код на email
4. Вернуть успех

POST /api/auth/verify

Цель: Подтвердить email и выдать токен

ПараметрТипОписание
emailstringEmail пользователя
codestring6 цифр из письма

Успех (200) + HttpOnly cookie:

{ "message": "Регистрация подтверждена" }

Логика:

1. Найти пользователя по email
2. Проверить verificationCode и срок
3. Сгенерировать ТОКЕН (64 символа)
4. Вычислить СЛЕПОК из запроса
5. Обновить пользователя:
- token = новый_токен
- tokenExpiresAt = now + 7 дней
- fingerprint = новый_слепок
- verificationCode = null
6. Установить HttpOnly cookie с токеном
7. Вернуть успех

POST /api/auth/login

Цель: Аутентификация и выдача токена

ПараметрТипОписание
emailstringEmail пользователя
passwordstringПароль

Успех (200) + HttpOnly cookie:

{ "message": "Вход выполнен" }

Логика:

1. Найти пользователя по email
2. Проверить пароль (bcrypt.compare)
3. Сгенерировать НОВЫЙ токен (старый умер)
4. Вычислить НОВЫЙ слепок устройства
5. Обновить пользователя:
- token = новый_токен
- tokenExpiresAt = now + 7 дней
- fingerprint = новый_слепок
6. Установить HttpOnly cookie
7. Вернуть успех
🔄 Важно: При каждом входе токен обновляется! Старое устройство больше не сможет войти автоматически.

GET /api/auth/check

Цель: Проверить токен и слепок, обновить токен если надо

Успех (200) + возможно новая cookie:

{
"user": {
"email": "user@example.com",
"status": "standard" // или premium/admin
}
}

Логика:

1. Получить токен из cookie
2. Найти пользователя по токену
3. Вычислить текущий слепок из запроса
4. Сравнить с fingerprint в БД:
- НЕ СОВПАДАЕТ → 401 (возможна кража)
5. Проверить срок токена:
- Если осталось < 1 дня:
* Генерируем новый токен
* tokenExpiresAt = now + 7 дней
* Устанавливаем новую cookie
6. Вернуть данные пользователя

POST /api/auth/forgot-password

Цель: Отправить код для сброса пароля

ПараметрТипОписание
emailstringEmail пользователя

Успех (200):

{
"message": "Если email зарегистрирован, код будет отправлен"
}

Логика:

1. Найти пользователя по email
2. Если найден:
- resetCode = generate6DigitCode()
- resetCodeExpiresAt = now + 15min
- Отправить код на email
3. Вернуть одинаковый ответ (безопасность)


POST /api/auth/reset-password

Цель: Установить новый пароль по коду

ПараметрТипОписание
emailstringEmail пользователя
codestring6 цифр из письма
newPasswordstringНовый пароль

Успех (200):

{
"message": "Пароль изменен, выполните вход"
}

Логика:

1. Найти пользователя по email
2. Проверить resetCode и срок
3. Обновить passwordHash
4. Очистить resetCode и resetCodeExpiresAt
5. НЕ МЕНЯТЬ ТОКЕН!
(пусть заново входит)
6. Вернуть успех

POST /api/auth/logout

Цель: Инвалидировать текущий токен

Успех (200) + очистка cookie:

{
"message": "Выход выполнен"
}

Логика:

1. Получить токен из cookie
2. Найти пользователя
3. Очистить токен и слепок:
- token = null
- tokenExpiresAt = null
- fingerprint = null
4. Очистить cookie
5. Вернуть успех

🖥️ Генерация слепка устройства ПОД ВОПРОСОМ!!!

function createFingerprint(req: Request): string { const data = { // Заголовки HTTP userAgent: req.headers['user-agent'], acceptLanguage: req.headers['accept-language'], acceptEncoding: req.headers['accept-encoding'], // Client Hints (современные браузеры) secChUa: req.headers['sec-ch-ua'], secChUaPlatform: req.headers['sec-ch-ua-platform'], secChUaMobile: req.headers['sec-ch-ua-mobile'], // IP (осторожно, может меняться) ip: req.ip || req.connection.remoteAddress, // DNT (Do Not Track) dnt: req.headers['dnt'] }; return crypto .createHash('sha256') .update(JSON.stringify(data)) .digest('hex'); }
🎯 Важно: Слепок считается на БЭКЕНДЕ из данных запроса. Фронтенд не участвует в его создании — это защищает от подделки!

🍪 Настройки HttpOnly cookie

res.cookie('authToken', token, {
httpOnly: true, // Недоступна из JavaScript (защита от XSS)
secure: true, // Только по HTTPS
sameSite: 'strict', // Защита от CSRF
maxAge: 7 * 24 * 60 * 60 * 1000, // 7 дней
path: '/' // Доступна на всех маршрутах
});

🛡️ Сценарии защиты

🎭 Кража токена

1. Хакер украл cookie с токеном
2. Пытается сделать запрос со своего устройства
3. Бэкенд вычисляет слепок хакера
4. Слепок НЕ совпадает с сохраненным в БД
5. Ответ: 401 Unauthorized
6. Токен не обновляется, хакер в пролете

📱 Смена устройства (легальная)

1. Пользователь заходит с нового ноутбука
2. Нет cookie → редирект на /login
3. Вводит email+пароль
4. Бэкенд обновляет слепок на новый
5. Выдает тот же самый токен (или новый)
6. Старое устройство больше не работает
💡 Гениальность схемы: Пользователь на одном устройстве может сидеть вечно — токен обновляется незаметно каждые 7 дней. При смене устройства — только один вход с паролем.

Общее описание

В качестве системы управления базами данных выбрана MongoDB. Это документо-ориентированная БД, которая идеально подходит для хранения пользовательских данных благодаря гибкой схеме и высокой производительности. Сервер БД развёрнут в Docker-контейнере, что обеспечивает изоляцию, простоту развёртывания и воспроизводимость окружения.

📦 MongoDB в Docker: 
docker run -d -p 27017:27017 --name mongodb-auth mongo:latest
👥

Коллекция users

Основная и единственная коллекция, хранящая всех пользователей системы.

📋 Схема документа

{
  "_id": ObjectId("507f1f77bcf86cd799439011"),

  // Учётные данные
  "email": "user@example.com",
  "passwordHash": "$2a$10$N9qo8uLOickgx2ZMRZoMye...",
  "role": "user",                // "user" или "admin"

  // Главный секретный токен (вечный)
  "secretToken": "a1b2c3d4e5f6...",  // SHA-256 хеш случайной строки

  // Доверенные устройства пользователя
  "trustedDevices": [
    {
      "fingerprint": "хеш_устройства_1",
      "lastSeen": "2024-03-12T10:30:00Z",
      "deviceName": "Chrome на Windows"
    },
    {
      "fingerprint": "хеш_устройства_2",
      "lastSeen": "2024-03-11T15:20:00Z",
      "deviceName": "Safari на iPhone"
    }
  ],

  // Метаданные
  "createdAt": "2024-01-15T10:00:00Z",
  "updatedAt": "2024-03-12T10:30:00Z"
}

🔍 Индексы для быстрого поиска

📧 email

  • Уникальный индекс
  • Поиск при логине
  • Проверка уникальности при регистрации

🔑 secretToken

  • Быстрый поиск по токену
  • Используется при каждом запросе
db.users.createIndex({ "email": 1 }, { unique: true });
db.users.createIndex({ "secretToken": 1 });
🖥️

Слепок устройства (fingerprint)

Ключевой элемент безопасности — привязка сессии к конкретному устройству пользователя.

📊 Из чего формируется

  • User-Agent (браузер, ОС)
  • Accept-Language (язык)
  • IP-адрес (первые октеты)
  • Заголовки Accept, Encoding

⚙️ Как создаётся

  • Сбор данных из заголовков
  • Конкатенация в строку
  • Хеширование (SHA-256)
// Пример создания слепка const data = `${userAgent}|${acceptLanguage}|${ipPrefix}`; const fingerprint = crypto.createHash('sha256') .update(data) .digest('hex');
🛡️ Важно: Слепок никогда не передаётся клиенту. Он хранится только в БД и используется исключительно для сравнения на сервере.
🔄

Основные операции с БД

📝 Регистрация

db.users.insertOne({
  email,
  passwordHash,
  secretToken,
  trustedDevices: [newDevice],
  createdAt: new Date()
})

🔐 Логин

db.users.updateOne(
  { email },
  { $addToSet: { trustedDevices: newDevice } }
)

✅ Проверка токена

db.users.findOne({
  secretToken,
  "trustedDevices.fingerprint": currentFingerprint
})
🔒

Безопасность данных

🔑 Пароли

  • Хешируются bcrypt (соль 10 раундов)
  • Никогда не хранятся в открытом виде

🎫 Токены

  • Генерируются через crypto.randomBytes()
  • Хранятся в БД как SHA-256 хеши

📧 Email

  • Индексирован для быстрого поиска
  • В планах — шифрование
🔗

Интеграция с микросервисами

Другие сервисы (заказы, оплата, уведомления) проверяют валидность сессии через внутренний API:

POST /internal/validate
Headers: X-Internal-Token: секретный_ключ
Body: { "token": "секретный_токен_пользователя" }

Response:
{
  "valid": true,
  "userId": "507f1f77bcf86cd799439011",
  "role": "user"
}
✅

Итоговая схема работы

Запрос с кукой → Поиск по secretToken → Сравнение fingerprint → Доступ ✅ / 401 ❌
📌 Ключевые особенности:
  • Одна коллекция users — простота и прозрачность
  • «Вечный» токен + слепок устройства — безопасность без сложной ротации
  • HttpOnly куки — защита от XSS
  • Множество доверенных устройств — удобство для пользователя
